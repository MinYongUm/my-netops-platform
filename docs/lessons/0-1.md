## Steps

### 1. Repository skeleton

- git 신원: user.name, user.email(GitHub noreply 주소), init.defaultBranch main
- SSH 키 생성 후 GitHub 등록, `ssh -T git@github.com`으로 인증 확인, SSH URL로 clone
- .gitignore 4줄: `.env*`, `!.env.example`, `sites/*.json`, `!sites/SITE-EXAMPLE.json`
  - 예외(`!`)는 막는 규칙 뒤에 와야 한다. 상위 디렉터리를 통째로 ignore하면 예외가 죽는다.
  - 검증: 가짜 파일을 만들고 `git status --short`와 `git check-ignore -v`로 확인 후 삭제

```
mkdir -p sites
touch .env sites/real-site.json sites/SITE-EXAMPLE.json
git status --short            # ?? .gitignore, ?? sites/ 두 줄만
git check-ignore -v .env sites/real-site.json
rm .env sites/real-site.json sites/SITE-EXAMPLE.json && rmdir sites
```

- .env.example(placeholder만), README.md 뼈대, 이 문서 뼈대
- 커밋: `chore: 기본 설정 파일 추가`

### 2. PostgreSQL

- compose.yaml: 최상위 `name: netops`(공용 서버에서 다른 프로젝트와 이름 충돌 방지), 서비스 `db`
  - image 고정(`postgres:16-alpine`): Zabbix 7.0의 모든 패치 버전이 지원하는 메이저. `latest`는 메이저가 바뀌면 데이터 디렉터리 포맷이 달라 기동 거부
  - environment: `${POSTGRES_USER:?missing in .env}` 형식. 변수가 없으면 기동 전에 실패
  - volumes: named volume `pg-data` → `/var/lib/postgresql/data`. 최상위 `volumes:`에 선언 필요
  - `ports:` 없음. 5432는 compose 내부 네트워크에서만 사용
- .env 생성

```
cp .env.example .env
sed -i "s/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$(openssl rand -hex 16)/" .env
```

- 확인

```
docker compose config | grep -v PASSWORD        # ${...}가 값으로 치환됐는지
docker compose up -d
docker compose ps                                # netops-db-1 Up, PORTS 5432/tcp (publish 없음)
docker compose exec db psql -U zabbix -d zabbix -c 'select version();'   # PostgreSQL 16.x
docker volume ls | grep netops                   # netops_pg-data
git status --short                               # .env가 보이면 안 됨
```

- 커밋: `feat: PostgreSQL 서비스 추가`

### 3. Zabbix Server

- 최신 패치 태그 조회

```
curl -s "https://hub.docker.com/v2/repositories/zabbix/zabbix-server-pgsql/tags?name=alpine-7.0.&page_size=100" \
  | grep -o '"name":"alpine-7\.0\.[0-9]*"' | sort -t. -k3 -n | tail -3
```

- 서비스 `zabbix-server`: image `alpine-7.0.31`, environment `DB_SERVER_HOST: db` + POSTGRES_* 3개
  - 서비스 이름이 compose 내부 DNS 이름. IP를 적지 않는다
  - Zabbix 이미지가 DB 접속 정보를 postgres 이미지와 같은 변수명(POSTGRES_*)으로 읽는다
  - `ports:` 없음. 10051은 능동 agent가 붙을 때만 필요
- 첫 기동: `** Creating 'zabbix' schema in PostgreSQL` 후 약 8초 뒤 `server #0 started`. 테이블 203개

```
docker compose exec db psql -U zabbix -d zabbix -c "select count(*) from pg_tables where schemaname='public';"
```

- 기동 순서 실험: `docker compose stop db` 후 `restart zabbix-server`. 서버는 죽지 않고 `PostgreSQL server is not available. Waiting 5 seconds...`를 약 15초 주기로 반복. 에러는 refused가 아니라 DNS 이름 소멸. 그동안 `ps`는 Up. `start db` 후 다음 재시도에서 `Table 'zabbix.dbversion' already exists`를 보고 스키마 생성을 건너뛰고 기동
- 해결: db에 healthcheck, zabbix-server에 depends_on

```
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -h 127.0.0.1 -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 5s
      timeout: 3s
      retries: 10
      start_period: 10s
```

```
    depends_on:
      db:
        condition: service_healthy
```

  - `-h 127.0.0.1`: postgres 초기화 중 임시 서버는 unix socket만 열어서 host 없이 돌리면 가짜 healthy
  - `$$`: Compose가 치환하지 않고 컨테이너 셸에 `$`로 전달. `docker inspect --format '{{json .Config.Healthcheck.Test}}' netops-db-1`로 확인
- 검증: `down -v` 후 `up -d` 출력에서 `db Healthy` → `zabbix-server Started`, `ps`에 `(healthy)`
- 커밋: `feat: Zabbix Server 서비스 추가`, `feat: DB healthcheck 추가 및 기동 순서 지정`

### 4. Zabbix Web

- .env에 `TZ=Asia/Seoul` 추가 (.env.example에도)
- 서비스 `zabbix-web`: image `alpine-7.0.31`, depends_on db(service_healthy) + zabbix-server(service_started), environment DB_SERVER_HOST + POSTGRES_* + `ZBX_SERVER_HOST: zabbix-server` + `PHP_TZ: ${TZ}`, ports `"${ZBX_WEB_PORT}:8080"`
  - ports는 따옴표 필수 (YAML 60진수 함정)
  - 이 이미지는 자체 HEALTHCHECK 내장. `ps`에 `(healthy)`
- 확인: `curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8081/` → 200
- 브라우저: `Admin` / `zabbix` 로그인 직후 비밀번호 변경. Reports → System information에서 `Zabbix server is running: Yes`, `zabbix-server:10051`
- 커밋: `feat: Zabbix Web 서비스 추가`

### 5. Grafana

- 버전 조회

```
curl -s "https://hub.docker.com/v2/repositories/grafana/grafana/tags?name=13.&page_size=100" \
  | grep -oE '"name":"13\.[0-9]+\.[0-9]+"' | cut -d'"' -f4 | sort -V | tail -3
curl -s https://api.github.com/repos/grafana/grafana-zabbix/releases/latest | grep -oE '"tag_name": *"[^"]+"'
```

- .env에 `GRAFANA_ADMIN_PASSWORD` 추가. Grafana가 첫 기동 때 한 번만 읽는다
- 서비스 `grafana`: image `grafana/grafana:13.2.4`, depends_on zabbix-web(service_healthy), environment GF_SECURITY_ADMIN_USER/PASSWORD + `GF_PLUGINS_PREINSTALL_SYNC: alexanderzobnin-zabbix-app@6.9.1` + TZ, volume `grafana-data` → `/var/lib/grafana`, ports `"${GRAFANA_PORT}:3000"`
  - `_SYNC`: 플러그인 설치가 끝난 뒤 HTTP 서버가 뜬다 (로그 행 번호로 확인: 설치 1835행 < Listen 1875행)
- 확인: `curl -s http://localhost:3000/api/health` → database ok
- Zabbix 쪽 읽기 전용 계정 (UI)
  - Users → User groups → `grafana`, Host permissions: `Zabbix servers` Read
  - Users → Users → `grafana`, Groups `grafana`, Role `User role`
  - Users → API tokens → `grafana`, 만료 없음. 토큰은 비밀번호 관리자에만 저장
- Grafana 쪽 (UI)
  - Administration → Plugins and data → Plugins → Zabbix → Enable
  - Connections → Data sources → Zabbix: URL `http://zabbix-web:8080/api_jsonrpc.php`, Auth type API token
    - 컨테이너 간 통신이므로 서비스 이름 + 내부 포트. 호스트 포트 8081은 밖에서 들어올 때만
  - Save & test → `Zabbix API version: 7.0.31`
  - Explore → Group `Zabbix servers`, Host `Zabbix server`, Item `Number of processed values per second` → 그래프 확인
- 커밋: `feat: Grafana 서비스 추가`

### 6. 삭제 → 재설치 검증

- `docker compose down` → `up -d`: 데이터 유지. Zabbix 변경한 비밀번호, Grafana 데이터소스, 이전 그래프 데이터 그대로
- `docker compose down -v` → `up -d`: 기동 순서와 시간이 동일 (db Healthy 6.4s → zabbix-server 5.8s → zabbix-web Healthy 11.9s → grafana 12.0s). 스키마 재생성 8초. 플러그인 동기 설치 후 HTTP Listen
- `down -v` 후 사라지는 것 = Lesson 0-2 자동화 대상
  - Zabbix: Admin 기본 비밀번호 변경, 사용자 그룹 grafana(Read), 사용자 grafana, API 토큰
  - Grafana: Zabbix 앱 활성화, 데이터소스 등록(URL + 토큰)
